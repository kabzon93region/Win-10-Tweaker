# Находки и ограничения

Сюда записывается всё, что выяснено по ходу работы и влияет на реализацию: поведение Windows,
ограничения API, обнаруженные краевые случаи. Каждая запись — с доказательством (тест, лог, файл).

## Формат

```
### F-XX. Краткая формулировка
Что выяснено: …
Доказательство: файл/лог/тест/команда
Влияние: что меняем в реализации
Статус: подтверждено | требует проверки | unknown
```

### F-05. Ограничение окружения при запуске проверок
Что выяснено: процессы, запущенные из папки проекта (`target\...`), в этой среде не могут писать за пределы рабочей папки: создание каталогов в `%TEMP%` и `%LOCALAPPDATA%` возвращает `PermissionDenied`. Влияние: скрипты проверки копируют exe в `%TEMP%`; тесты не зависят от `%TEMP%`.
Статус: подтверждено.

### F-09. Устройство движка и журнала
Что выяснено: движок работает по схеме «снимок → действие → перечитывание → журнал». Журнал двухфазный: запись `started` с прежним состоянием пишется до изменения, `applied`/`failed` — после проверки. План идемпотентен: уже применённые действия попадают в `skipped`. Откат идёт в обратном порядке по `applied`-записям, проверяется повторным чтением; необратимый `ProcessRun` в откате помечается ошибкой. Незавершённые операции (`started` без финала) видны через `Journal::pending()` и откатываются `Engine::revert_pending()`.
Доказательство: `crates/tweaker-core/src/engine.rs` (32 теста), `journal.rs` (7 тестов), `fake.rs`; тесты `pending_operation_can_be_reverted`, `journal_survives_restart_between_apply_and_revert`.
Влияние: все пункты каталога дальше описываются только данными `action`-списков; UI и CLI будут вызывать один и тот же движок.
Статус: подтверждено.

### F-17. Планировщик задач без COM
Что выяснено: `IScheduler` реализован поверх `schtasks.exe`: список задач в папке — `schtasks /Query /FO CSV /NH` (только путь и имя, без состояний), состояние — `schtasks /Query /TN <path> /XML` с разбором `<Enabled>`, переключение — `schtasks /Change /TN <path> /ENABLE|/DISABLE`. Это устойчиво к языку системы в отличие от текстового `Ready/Disabled` в CSV, не требует COM-регистрации и работает на Win10/11. XML приходит в UTF-16 — декодируется как UTF-16LE, при отсутствии BOM — как UTF-8. Процессы запускаются с `CREATE_NO_WINDOW`, путь берётся как `%SystemRoot%\System32\schtasks.exe`, чтобы подмена по `PATH` не сработала. Сопоставление идёт по последнему сегменту пути (имени задачи), поэтому папки вроде `\Microsoft\Windows\PI` не мешают префиксам. Пункты, зависящие от необязательного ПО (Office, NVIDIA), помечены `"optional": true`: если задач нет, действие считается выполненным (ничего менять не нужно), а не переводит весь пункт в «недоступно».
Доказательство: `crates/tweaker-windows/src/scheduler.rs` (5 тестов), `crates/tweaker-core/src/action.rs` (`TaskSetEnabled`, `TaskSetEnabledMatching` с `optional`), 6 ENGINE-тестов (применение, идемпотентность, откат, недоступность, необязательное отсутствие).
Влияние: PRIV-03/04/05 применяются и откатываются теми же шагами, что реестр; имена задач PRIV-05 (17 префиксов) сверены с реальным списком задач этого ПК: найдены Microsoft Compatibility Appraiser, ProgramDataUpdater, StartupAppTask, PcaPatchDbTask, Sqm-Tasks, GatherNetworkInfo, Microsoft-Windows-DiskDiagnosticDataCollector, QueueReporting, UsbCeip, Consolidator, DmClient, WinSAT, Proxy; PcaGeneralDb0/1 и KernelCeipTask на этом ПК отсутствуют — это нормально, они есть не на всех редакциях.
Статус: подтверждено (чтение, перечисление и сверка имён на этом ПК), запись — только фейки.

### F-20. Приёмочные тесты каталога без ручного перечисления
Что выяснено: вместо 17 отдельных ручных тестов сделан файл `crates/tweaker-core/tests/privacy_section.rs`: тест на каждый ID генерируется макросом, а состояние фейковой машины готовится по списку действий самого пункта (службы, задачи по префиксам, hosts). Проверяется: план равен числу действий, `before` каждого шага сверяется с посеянным состоянием (реестр — значения нет, служба — Running/Automatic, задачи — включены, hosts — исходный текст), detect = Applied после применения, повторный план пуст, откат возвращает ровно столько же действий, второй откат — no-op, `applied_ops` пуст.
Доказательство: `crates/tweaker-core/tests/privacy_section.rs` (21 тест: 17 по пунктам + обратимость действий + отсутствие служб + ошибки записи hosts и реестра; в обоих случаях проверяется текст ошибки в отчёте и запись `Failed` с текстом в журнале); `cargo test --workspace` — 143 passed.

### F-21. Вторая копия программы
Что выяснено: до этапа 4 два окна могли работать одновременно и писать в один журнал, мешая откату. Добавлен сессионный мьютекс `Local\WinTweaker.Instance` (`single_instance.rs`): второе окно получает локализованное сообщение и закрывается с кодом 0. Автоматические режимы (`--selftest`, `--smoke`, `--screenshot`) намеренно не проверяют мьютекс, чтобы тесты и снимки могли идти параллельно. Мьютекс освобождается ядром даже после аварийного завершения.
Доказательство: `crates/tweaker-windows/src/single_instance.rs` (2 теста: повторный захват отклоняется, разные имена не конфликтуют), `message.rs`, `app::run`, ключи `instance.title`/`instance.body` (ru/en). Живой прогон: первая копия открыла окно, вторая завершилась с кодом 0, в логе `[WARN] instance: another copy is already running`, на экране — сообщение «WinTweaker уже запущен» (снимок рабочего стола).
Влияние: TESTPLAN 0.6 закрыт вариантом «запрет второй копии». Ограничение: мьютекс в пространстве `Local\` действует только в текущей сессии (дефект D-7); при необходимости — `Global\`.

На этом ПК установлено 6 из 24 приложений (Магазин, Фотографии, Xbox, Будильник, Диктофон, Камера), плитки показывают реальные состояния.

Влияние: удаление пакета, установленного для всех пользователей, может быть недоступно без прав администратора; приложение вернётся только пока его файлы лежат в `WindowsApps`, иначе показывается подсказка про Магазин.
Статус: подтверждено (чтение, рендер, тесты на фейках); живые удаление/восстановление — этап 8.

### F-39. Очистка, оптимизация, прогресс и отмена
Что выяснено: очистка сделана отдельным действием `CleanPaths`: движок не делает снимок (удалённые кэши не восстановить), адаптер обходит папки, суммирует освобождённые байты и пропускает занятые файлы в отчёт, а корневые папки остаются на месте. Объём считается по кнопке «Рассчитать объём»: обход `C:\Windows` и браузерных профилей занимает больше 20 секунд и не должен тормозить первый кадр (таймаут снимка). Применение каталога теперь идёт в фоновом потоке: прогресс по действиям, отмена между действиями, отчёт «+применено / =пропущено / !ошибок» и «освобождено N». Для обратимых пунктов оптимизации (`compact`, `powercfg`) откат идёт командами из данных. При старте читается журнал: незавершённые операции показываются баннером с кнопками «Откатить» и «Скрыть».
Доказательство: `crates/tweaker-core/src/action.rs` (`CleanPaths`), `engine.rs` (`apply_with`, `freed_bytes`, отказ откату), `adapters.rs` (`CleanStats`), `crates/tweaker-windows/src/files.rs` (обход, `%VAR%`, пропуск занятых), `crates/tweaker-app/src/app.rs` (`ApplyJob`, `pending_recovery`), тесты `cleanup_reports_freed_bytes_and_cannot_be_reverted`, `apply_stops_between_actions_when_cancelled`, `cleanup_removes_contents_and_keeps_the_root`, снимки `cleaner.png`, `optimization.png`.
Влияние: отмена не прерывает уже начатую команду (`compact`/`dism`), она останавливает следующий шаг; это записано в D-38. Живая очистка на этом ПК не запускалась.
Статус: подтверждено (тесты и рендер); живые удаление и отмена — этап 8.

### F-40. Границы этапа 6
Что выяснено: не реализованы пункты, которым нужны новые операции вне текущих адаптеров: CLN-17 (права на служебные каталоги), CLN-START (создание задачи автозапуска с `--clean`), OPT-05 (список сторонних драйверов и удаление выбранных), OPT-06 (поиск дубликатов и жёсткие ссылки). Для них нужны отдельные решения владельца и новые действия (`TaskCreate`, `IAppx`-подобный `IDriverStore`, `Hardlink`); молчаливая реализация «удалить всё» нарушила бы правила проекта.
Доказательство: `docs/DECISIONS.md` D-39, `FEATURES.md` разделы 6 и 9, отсутствие этих id в `cleaner.json`/`optimization.json`.
Влияние: раздел очистки показывает 16 пунктов вместо 18, оптимизации — 4 вместо 6; OPT-01/03 без выбора алгоритма, CLN-11 — 5 корней вместо 38, CLN-04 без Firefox/Cent (D-45).
Статус: подтверждено (исключения зафиксированы).

### F-41. Сервисные разделы
Что выяснено: системная информация собирается одним CIM-запросом PowerShell (ОС, версия, установка, загрузка, CPU, RAM, компьютер, GPU, мониторы, диски, сеть) и показывается таблицей с копированием и сохранением в `%LocalAppData%\WinTweaker\config\sysinfo.txt`; вывод принудительно переводится в UTF-8, иначе кириллица в названиях ОС и мониторов превращалась в ромбы. Раздел «Сервис» получил 4 пункта (точка восстановления, `rstrui`, экспорт и импорт драйверов), «Обслуживание» — 6 исправлений (F8, MSI Extract, Edge, cmd в меню, NumLock, битые ярлыки); всё применяется только по явной команде. VirusTotal не реализован: нужен ключ API. Профиль и проверка обновлений добавлены позже (F-43, F-44).
Доказательство: `crates/tweaker-windows/src/os.rs` (`WindowsSystemInfo::report`, `rows_from_json`), `crates/tweaker-app/src/app.rs` (`draw_sysinfo`), `crates/tweaker-core/data/tweaks/{backup,maintenance}.json`, тесты `parses_cim_report_into_rows`, `live_report_contains_os_and_cpu`, приёмочные тесты 4+6, снимки `sysinfo.png`, `backup.png`, `maintenance.png`.
Влияние: VirusTotal остаётся выключенным до ключа; профиль и обновления реализованы.
Статус: подтверждено (реальные данные и рендер); живое создание точки восстановления и импорт драйверов не выполнялись.

### F-42. Ограничения сервисных пунктов
Что выяснено: BKP-03 экспортирует только драйверы в `%LocalAppData%\WinTweaker\backups\drivers`; HTML-список установленных программ и выбор папки из требований не сделаны (D-49). BKP-04 импортирует только `.inf` из этой же папки и теперь отказывается помечать пункт применённым, если файлов нет. FIX-06 удаляет битые ярлыки без снимка (необратимо), но только после общего предпросмотра и подтверждения; это отмечено в описании D-49. BKP-01 зависит от троттлинга `Checkpoint-Computer` (не чаще раза в 24 часа) — при отказе PowerShell пункт получает ошибку, а не «готово».
Доказательство: `backup.json` (BKP-03/04), `maintenance.json` (FIX-06), `docs/DECISIONS.md` D-49, `docs/FINDINGS.md` F-41.
Влияние: список программ и выбор папки — после решения владельца; живое создание точки и импорт не выполнялись.
Статус: подтверждено (ограничения зафиксированы).

### F-43. Профиль настроек и права на служебные каталоги
Что выяснено: профиль хранит только ID включённых пунктов (`config\profile.json`, версия 1); экспорт собирает применённые пункты по всем разделам, импорт читает файл, показывает список с названиями и применяет выбранное в фоне после подтверждения. Неизвестные ID пропускаются с пометкой. CLN-17 выдаёт группе «Пользователи» права изменения на `Windows\Temp` и `SoftwareDistribution\Download` через `icacls`, чтобы очистка могла удалить занятые файлы; пункт помечен высоким риском и требует подтверждения.
Доказательство: `crates/tweaker-core/src/profile.rs` (4 теста), `crates/tweaker-app/src/app.rs` (`export_profile`, `prepare_profile_import`, `confirm_profile_import`), `crates/tweaker-core/data/tweaks/cleaner.json` (CLN-17), тест `cleaner_17_service_acl`, снимок `about.png`.
Влияние: профиль не сохраняет значения и снимки (D-50); проверка обновлений добавлена в F-44/D-53.
Статус: подтверждено (тесты, рендер); живой импорт и `icacls` не выполнялись.

### F-44. Проверка обновлений и публикация
Что выяснено: у проекта не было git remote и GitHub-репозитория; по решению владельца создан публичный `https://github.com/kabzon93region/Win-10-Tweaker`, ветка `master` запушена, выпущен релиз `v0.1.0` с бинарником. Кнопка «Проверить обновления» в about читает последний тег через GitHub API и сравнивает с `0.1.0`; при совпадении пишет «установлена последняя версия». Скачивание и установка не выполняются (D-53).
Доказательство: `crates/tweaker-windows/src/update.rs` (нормализация тега + живой API), `crates/tweaker-app/src/app.rs` (`check_updates`), `gh api .../releases/latest` → `v0.1.0`, публичный репозиторий.
Влияние: проверка зависит от сети; подписанный манифест и автоустановка остаются на потом.
Статус: подтверждено (репозиторий, релиз, чтение тега); нажатие кнопки в UI не автоматизировано.
