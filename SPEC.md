# Техническое задание: «Твикер Windows» (чистая комната)

Документ описывает **что нужно сделать**, не описывая, как это было сделано в исходном продукте.
Исходный продукт в чистой комнате недоступен: ни бинарник, ни его исходники, ни материалы разборки.
Разрешён только этот пакет документов.

## 1. Продукт

Настольная утилита для настройки, очистки и диагностики Windows 7/8/8.1/10.
Один исполняемый файл, без установщика, запуск от имени администратора.
Интерфейс — на русском и английском, переключение по языку системы.

Пользователь открывает программу, видит список изменений с описанием и уровнем риска, отмечает
нужные, нажимает «Применить». Программа показывает, что именно будет изменено, выполняет изменения,
проверяет результат и ведёт журнал, по которому можно откатить любое действие.

## 2. Пользователи и сценарии

| Сценарий | Что делает пользователь | Результат |
|---|---|---|
| «Почистить систему» | выбирает пункты очистки, видит предполагаемый объём, применяет | удалён мусор, отчёт «освобождено N» |
| «Отключить телеметрию» | отмечает пункты конфиденциальности | изменения применены, состояние видно в интерфейсе |
| «Вернуть как было» | жмёт «Откатить» у пункта или «Откатить всё» | значения восстановлены из снимка |
| «Понять, что с компьютером» | открывает «Системная информация», копирует отчёт | текст в буфере/файле |
| «Проверить файл на вирусы» | перетаскивает файл, вводит ключ VirusTotal | отчёт по детекциям |
| «Сделать точку восстановления» | кнопка «Создать точку» | точка создана, подтверждение |

## 3. Границы

**Входит:** 4 раздела настроек (68 пунктов), 24 службы, 17 операций очистки, 24 приложения
магазина, автозагрузка (5 источников), 6 операций оптимизации, проверка VirusTotal, системная
информация, резервное копирование (точка восстановления, драйверы), экспорт/импорт профиля настроек,
двуязычный интерфейс, журнал с откатом.

**Не входит:** установка/обновление Windows, драйверы, антивирус, работа с сетью пользователя,
автоматические фоновые изменения без действия пользователя, скрытые проверки «свой/чужой».

## 4. Общие правила поведения

1. **Только явное действие.** Ни одно изменение системы не выполняется без нажатия пользователя.
   Автозапуск очистки включается отдельной галочкой и явно показывает, что будет запускаться.
2. **Предпросмотр.** Перед применением программа показывает список изменений: ключ/значение,
   файл/папка, команда, служба. Для опасных пунктов — отдельное подтверждение с текстом риска.
3. **Снимок и откат.** Перед изменением сохраняется прежнее состояние (значение реестра, файл,
   состояние службы). Откат возвращает ровно прежнее состояние; если прежнего значения не было —
   удаляет созданное. Журнал хранится локально и переживает перезапуск.
4. **Проверка после применения.** После записи значение перечитывается; при расхождении пункт
   помечается «ошибка» с причиной, а не «применено».
5. **Идемпотентность.** Повторное применение не создаёт дублей (правил брандмауэра, строк hosts,
   ключей автозапуска).
6. **Права.** Манифест `requireAdministrator`; при отказе от прав — понятное сообщение, а не падение.
7. **Никаких секретов в коде.** Ключи, пароли, адреса поддержки — только в конфигурации/на сервере.
8. **Ошибки видны.** Каждая неудача логируется (код, объект, текст) и показывается пользователю
   в отчёте; молчаливое проглатывание ошибок запрещено.
9. **Отсутствие изменений при запуске.** Старт программы не меняет систему (кроме чтения).

## 5. Интерфейс

Одной формы достаточно; структура — левое меню и рабочая область.

| Раздел | Содержимое |
|---|---|
| Конфиденциальность | 17 пунктов, у каждого: название, описание, состояние, риск |
| Контекстное меню | 17 пунктов + вложенные подпункты |
| Интерфейс | 17 пунктов |
| Система | 17 пунктов + «прокси-автоконфиг» |
| Службы | 24 службы: имя, описание, состояние (работает/остановлена/удалена), переключатель |
| Очистка | 17 пунктов + «автоочистка при входе», оценка объёма, прогресс |
| Приложения | 24 плитки: установлено/удалено, кнопки «Удалить»/«Восстановить» |
| Автозагрузка | 5 источников, переключатели, путь к объекту |
| Оптимизация | 6 операций с реальным прогрессом |
| Проверка на вирусы | ключ API, drag&drop, таблица детекций |
| Системная информация | отчёт о ПК, копирование/сохранение |
| Сервис | точка восстановления, восстановление, экспорт/импорт драйверов |
| О программе | версия, лицензия, обновление, обратная связь |

Требования к элементам:

- состояние пункта — три значения: «применено», «не применено», «недоступно» (с причиной);
- описание появляется при наведении и содержит: что делает, чем рискует пользователь, нужен ли
  перезапуск;
- кнопка «Применить» применяет отмеченное в текущем разделе; «Откатить» — возвращает выбранное;
- индикатор работы — детерминированный (по количеству шагов), с возможностью отмены;
- ошибки — список в конце операции, с кнопкой «Показать журнал».

## 6. Данные и модель

Каталог настроек — **данные, а не код**:

```
Tweak {
  Id            // "PRIV-01"
  Section       // privacy | context | ui | system | services | cleaner | apps | autorun | optimization
  TitleRu/En, DescriptionRu/En, RiskLevel, RequiresReboot
  Detect()      // текущее состояние: applied | notApplied | unavailable(reason)
  Plan()        // список действий: RegistrySet, RegistryDelete, FileWrite, FileDelete,
                // ServiceStart/Stop/Config, ProcessRun, FirewallRule, TaskChange, AppxRemove
  Apply(plan)   // выполняет, сохраняя снимок каждого действия в журнал
  Revert()      // по журналу или по детектору
}
```

Требования:

- все действия — через абстракции `IRegistry`, `IFileSystem`, `IServiceControl`, `IProcessRunner`,
  `IFirewall`, `IScheduler`, `IAppx`, `ISystemInfo` (тестируемость без реальной системы);
- журнал: `{timestamp, tweakId, action, before, after, result}` в JSONL рядом с exe (или в
  `%LocalAppData%\<Product>`), с ограничением размера и ротацией;
- профиль настроек (экспорт/импорт) — JSON с версией схемы и списком ID, без привязки к именам
  контролов;
- состояние «Pro» (если сохраняется) — отдельный сервис, не влияющий на базовые функции.

## 7. Архитектура (рекомендуемая)

```
Product.sln
 ├─ Product.Core        // модели Tweak/Plan/Action/Journal, движок применения, валидация
 ├─ Product.Windows     // адаптеры: реестр, файлы, службы, процессы, firewall, scheduler, appx
 ├─ Product.App         // WinForms (или WPF) UI, локализация, композиция
 ├─ Product.Tests       // xUnit: движок на фейковых адаптерах
 └─ Product.Cli         // опционально: применение профиля из командной строки
```

Правила:

- `Product.Core` не знает про Windows API и WinForms — только интерфейсы;
- каждый пункт каталога — отдельный класс-описание в `Tweaks/<Section>/<Id>.cs`, без «простыней»
  `if` в обработчиках кнопок;
- UI не содержит бизнес-логики: нажатие формирует команду «применить выбранные ID»;
- длительные операции — `async` с `CancellationToken` и реальным прогрессом.

## 8. Стек (решение владельца, рекомендация — вариант A)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. .NET Framework 4.8 + WinForms** | работает на Windows 7 SP1…11; минимум зависимостей; привычный вид | старый рантайм, нет новых API |
| B. .NET 8 + WinForms/WPF | современный C#, тесты, публикация одним файлом | не работает на Windows 7 |
| C. .NET 8 + Avalonia | кроссплатформенный UI | тяжелее, не нужен для задачи |

Если Windows 7 не требуется — брать B. Если требуется — A. Решение фиксируется в начале работы.

## 9. Безопасность и этика (обязательные требования)

1. **Никаких скрытых изменений** при старте, в фоне и «по расписанию» без явного включения.
2. **Опасные операции** (удаление системных каталогов, `hosts`, брандмауэр, службы) — только с
   предпросмотром и подтверждением; список того, что будет удалено, показывается до выполнения.
3. **Запрещено удалять** без явного отдельного подтверждения: `C:\Recovery`, `C:\Minidump`,
   `C:\$Windows.~BT`, `C:\$Windows.~WS`, `BOOTSECT.BAK`, `hiberfil.sys`, `WinSxS`, `DriverStore`,
   `SoftwareDistribution\DataStore`, `FNTCACHE.DAT`, языковые каталоги системы.
   Вместо удаления — «показать размер и предложить штатный способ» (`cleanmgr`, `Dism`, `powercfg`).
4. **hosts** — только собственный блок с маркерами
   (`# >>> Product telemetry block >>>` … `# <<<`), добавление/удаление идемпотентно, файл не
   перезаписывается целиком.
5. **Брандмауэр** — правила с префиксом продукта, удаление только своих.
6. **Обновления** — по HTTPS с проверкой подписи пакета (Ed25519/RSA) и хэша; никакого
   само-переписывания через `taskkill/del/ren`; при неудаче — сообщение и ручная установка.
7. **Сторонние утилиты** не скачиваются и не запускаются автоматически.
8. **Лицензия** — если нужна платная версия: токен, подписанный сервером, привязанный к аккаунту,
   с офлайн-проверкой подписи; никаких «код = серийник железа» и списков «плохих» машин.
9. **Приватность** — никакой отправки данных без действия пользователя; VirusTotal — только явная
   загрузка выбранного файла с предупреждением.
10. **Логи** не содержат секретов и путей пользователя сверх необходимого.

## 10. Надёжность и производительность

- любое действие длительнее 200 мс — с индикатором и возможностью отмены;
- ошибка одного пункта не прерывает остальные; итог — отчёт «успешно/ошибки»;
- повторный запуск после сбоя: журнал позволяет завершить или откатить незавершённое;
- потребление памяти в покое — до 150 МБ; запуск — до 2 с на SSD;
- нет блокировки UI на время операций.

## 11. Локализация

- все строки — в ресурсах (`.resx`/`ResourceManager`), без ручного разбора текстовых файлов;
- русский и английский полностью; отсутствующая строка — ошибка сборки/теста, а не пустой текст;
- форматы чисел/дат — по культуре.

## 12. Логирование и диагностика

- журнал изменений (см. п.6) + технический лог (уровни INFO/WARN/ERROR) в
  `%LocalAppData%\<Product>\logs`;
- кнопка «Экспорт диагностики» — zip с логами и версией системы (без секретов).

## 13. Приёмка

Продукт считается готовым, когда:

1. реализованы все пункты из `FEATURES.md` (или явно согласованы как «не делаем»);
2. у каждого пункта работают Detect/Apply/Revert и есть автотест на фейковых адаптерах;
3. на чистой ВМ каждый пункт применяется и откатывается, состояние после отката совпадает со
   снимком до применения (проверка по `reg export` и хэшам файлов);
4. ни одно действие не выполняется без подтверждения; старт программы не меняет систему;
5. сборка воспроизводима, тесты зелёные, логи и журнал работают;
6. пройден чек-лист `TESTPLAN.md`.
