# Правила чистой комнаты

Эта папка — независимая реализация утилиты настройки Windows по документации.
Здесь **нельзя** использовать оригинальный продукт и его разборку.

## Изоляция

1. Запрещено открывать, копировать и цитировать:
   - оригинальный исполняемый файл продукта и любые его копии;
   - исходники, дампы, ресурсы, скрипты и документы его разборки — в любой папке;
   - любые производные материалы (декомпиляция, расшифрованные строки, извлечённые ресурсы).
2. Единственный источник требований — файлы этой папки: `SPEC.md`, `FEATURES.md`, `TESTPLAN.md`.
3. Если для реализации не хватает факта (имя ключа, поведение, текст) — спросить владельца,
   а не «подсмотреть» в исходниках. Неизвестное помечать `unknown` и выносить в вопросы.
4. Реестровые пути и команды из `FEATURES.md` — это требования к поведению, их можно использовать.
   Внутреннее устройство старого продукта (классы, методы, структура кода) не воспроизводится.

## Разработка

5. **Один этап за раз.** Этап = проверяемый результат (собирается, тесты зелёные, есть отчёт).
6. **Сначала каркас и движок, потом пункты.** Не писать 68 пунктов до того, как работает
   apply/detect/revert/журнал на одном пункте.
7. **Данные вместо кода.** Каждый пункт — описание в каталоге (`Tweaks/...`), а не ветка `if` в UI.
8. **Абстракции.** Ядро не знает про Windows API: только интерфейсы `IRegistry`, `IFileSystem`,
   `IServiceControl`, `IProcessRunner`, `IFirewall`, `IScheduler`, `IAppx`, `ISystemInfo`.
9. **Снимок и откат** для каждого действия; повторное применение идемпотентно.
10. **Проверка после применения**: перечитать значение; расхождение — «ошибка», а не «готово».
11. **Никаких скрытых действий**: старт программы систему не меняет.
12. **Никаких секретов в коде**: ключи/пароли/адреса — в конфигурации или запросе у пользователя.
13. **Опасные операции** (🔴 в `FEATURES.md`) — только с предпросмотром и подтверждением.
14. **Только безопасные альтернативы**: не удалять системные каталоги, `hosts` менять блоком,
    брандмауэр — только свои правила, обновления — только с проверкой подписи.

## Качество

15. Код и идентификаторы — на английском; тексты интерфейса — в ресурсах (`.resx`), ru + en.
16. Тесты: unit для движка на фейковых адаптерах (обязательно для каждого пункта), ручные — по
    `TESTPLAN.md`.
17. Логи: INFO/WARN/ERROR в `%LocalAppData%\<Product>\logs`, без секретов, с ротацией.
18. Журнал изменений (JSONL): `{ts, tweakId, action, before, after, result}`; переживает перезапуск.
19. Сборка воспроизводима; версия и хэш фиксируются в `docs/STATE.md`.
20. Документация в этой папке: `docs/STATE.md` (этапы), `docs/DECISIONS.md` (принятые решения),
    `docs/FINDINGS.md` (что выяснено по ходу), `docs/index.md`.

## Общение

21. Отвечать по-русски; отчёт об этапе — коротко: что сделано, чем проверено, что дальше.
22. Перед изменением требований — согласовать с владельцем и записать в `docs/DECISIONS.md`.
